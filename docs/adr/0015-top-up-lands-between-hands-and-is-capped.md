# 补码命令随时能发，但只在两手牌之间落地，且不超过牌桌带入线

`topup 200` 任何时候都能发出去，服务端先收下；筹码在下一手牌开始之前才真正加到 Stack 上，并广播一条 `top_up` 事件。牌局进行中发的补码不会被拒绝，也不会中途改变任何人的筹码。补码后的 Stack 不得超过 `--buyin`——那个数既是默认带入，也是这张桌的带入上限。

「只能发生在两手牌之间」是规则，但把它做成「时机不对就报错」会把授时的责任推给客户端：agent 拿不到「现在是不是两手牌之间」这个信号，只能靠猜，猜错就得重试。收下再延迟落地，规则一样守住了，而客户端不需要掐点。设上限则是因为没有上限的话，一个 agent 可以在任意时刻把自己变成桌上最深的筹码，评测里的筹码深度就不再是可控变量——真实牌桌用最大带入解决这个问题，这里照搬。
