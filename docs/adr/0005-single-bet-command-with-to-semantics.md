# 只有一个下注命令 `bet`，且永远是「加注到」语义

`bet 100` 的含义是「把我在当前 Street 上的总投入推到 100」，而不是「在对手基础上再加 100」。我们不提供 `raise` 命令——传统术语里的下注与加注在语义上是同一件事，区别只在此前有没有人下注过。人在终端里另有 `f` / `b` / `a` 三个单字母快捷输入，但它们只活在人这一侧。

「加注到」与「再加」的歧义是德州扑克 CLI 最经典的错误来源：两种语义都说得通，一旦人和 agent 各理解成一种，就会下错注且不报错。选 to 语义是因为真实牌桌就这么说话；砍掉 `raise` 是为了让这个歧义在命令表里根本无处存身。

## 单字母快捷输入（修订）

这一条原先写的是「不做单字母别名，因为打错一个字母就弃牌是不可逆的灾难」。现在做了，但只给三个：`f` fold、`b <数额>` bet、`a` allin。改的理由是实际打下来发现，真正在发生的不是打错字母，是每手牌敲四五遍 `check`——打字量本身就在把人从牌局里拽出来，而每一次多敲的五个字母都有自己的手滑机会。

给谁不给谁，判据只有一条：**会认错的不给**。fold、bet、allin 三个词各自独一份，打出来就是那个意思。check 和 call 是命令表上唯一一对看着像的动作，都以 c 开头，认错的代价是本该过牌却跟了注，或者反过来——所以两个都不给，一起写全。给其中一个而另一个没有是最坏的选项：那种规则得先想一下才敢敲，而快捷输入的全部意义就是不用想。sitout 和 sitin 同理，`s` 谁也没拿到。

不给不等于不说话。敲 `c`、`k` 或 `s` 都会得到一句说得清的回复（「这两个太像了，都要写全」），而不是掉进「不认识的动作」里——后者会让人以为自己打错了字，于是再试一遍。故意不给和没见过是两件事，话要说得不一样。

真正要守住的边界是别名只存在于人敲的那一行。解析别名的是 `poker.ParseAction`，它只有一个调用方，就是人类客户端读 stdin 那一处；JSON 线路走 `protocol.Command.Action()`，是另一个 switch，每个动作永远只有一种拼法。写 agent 的人照着 `your_turn` 里的动作名发命令就该一次成功，不必知道别名存在，更不该被迫去认第二种写法——一个字段有两种合法写法，两边各实现一半就是协议开始烂掉的地方。`internal/protocol/protocol_test.go` 里有一条守着它。
