# 只有一个下注命令 `bet`，且永远是「加注到」语义

`bet 100` 的含义是「把我在当前 Street 上的总投入推到 100」，而不是「在对手基础上再加 100」。我们不提供 `raise` 命令——传统术语里的下注与加注在语义上是同一件事，区别只在此前有没有人下注过。人在终端里另有 `f` / `k` / `c` / `b` / `a` 五个单字母快捷输入，但它们只活在人这一侧。

「加注到」与「再加」的歧义是德州扑克 CLI 最经典的错误来源：两种语义都说得通，一旦人和 agent 各理解成一种，就会下错注且不报错。选 to 语义是因为真实牌桌就这么说话；砍掉 `raise` 是为了让这个歧义在命令表里根本无处存身。

## 单字母快捷输入（修订）

这一条原先写的是「不做单字母别名，因为打错一个字母就弃牌是不可逆的灾难」。现在做了：`f` fold、`k` check、`c` call、`b <数额>` bet、`a` allin。改的理由是实际打下来发现，真正在发生的不是打错字母，是每手牌敲四五遍 `check`——打字量本身就在把人从牌局里拽出来，而每一次多敲的五个字母都有自己的手滑机会。快捷输入没有制造新的风险，它换掉的是另一种。

`k` 是 check、`c` 是 call 不是按首字母排的，是牌桌上本来就这么说；两个词都以 c 开头，抢到 c 的是更常用的那个。`s` 谁也没给：sitout 和 sitin 都以 s 开头，而猜错的代价是「本来想回座，结果又暂离一手」，所以 `s` 只回一句话说清 `so` 和 `si`，什么都不做。

真正要守住的边界是别名只存在于人敲的那一行。解析别名的是 `poker.ParseAction`，它只有一个调用方，就是人类客户端读 stdin 那一处；JSON 线路走 `protocol.Command.Action()`，是另一个 switch，每个动作永远只有一种拼法。写 agent 的人照着 `your_turn` 里的动作名发命令就该一次成功，不必知道别名存在，更不该被迫去认第二种写法——一个字段有两种合法写法，两边各实现一半就是协议开始烂掉的地方。`internal/protocol/protocol_test.go` 里有一条守着它：把五个字母当命令类型发过去，必须一条都不认。
