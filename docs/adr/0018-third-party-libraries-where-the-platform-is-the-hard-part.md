# 可以引第三方库，但只在「难的是平台本身」的地方

零依赖不再是硬约束。取舍的标准是：这件事难在哪。难在**外部世界的事实**——终端是不是终端、这个字素在屏幕上占几列、怎么开一个 pty——就引库，因为那些事实不是想清楚就能得出的，是查表和 ioctl，而表和 ioctl 由别人维护得更好。难在**这个牌局本身**——牌力怎么比、边池怎么分、事件该给谁看——就自己写，因为那是这个项目要表达的东西，交出去等于把要说的话交出去。

按这条标准，进来了三个：

- `golang.org/x/term`：判断对面是不是终端，以及终端多高。
- `github.com/mattn/go-runewidth`：一个字符串在等宽终端里占几列。
- `github.com/creack/pty`（只用在测试里）：开一个真终端来验收。

前两个各自替掉了一段自己手写的、**已经在骗人**的代码，这是它们能进来的真正理由——不是「用库更规范」，是「自己那份是错的」。

`os.ModeCharDevice` 从来就不是在问「是不是终端」，它问的是「是不是字符设备」，而 `/dev/null`、`/dev/zero`、串口全都是。于是 `poker join ... > /dev/null` 被判成终端，往里灌光标移动序列。`x/term` 走真正的 `TCGETS` ioctl，只有终端答得上来。这个判断同时管着上色和就地重画，错一次两处都错。

手写的那张东亚宽度范围表撑不住「名字是 `--as` 传进来的任意字符串」：组合符号（法语重音、泰文声调）被算成各占一列，ZWJ 拼出来的 emoji 被算成好几个字符，还漏掉了 U+1F0A0 那一块——扑克牌 emoji 🃏，一个扑克程序漏了它。每一处都让座位表歪一格，而歪掉的那一格不会有编译错误。真正难的部分是字素簇的切分，那正是这个库存在的理由。

`creack/pty` 换来的是一条以前不存在的测试。就地重画对不对，单元测试只能证明「上移的行数等于上一帧的行数」这个算术；屏幕最后长什么样，得把字节真写进一个终端再按 ANSI 的规矩解回来。以前这一步是我手跑一个脚本看一眼，而手跑过一次的东西改坏了没人会发现。现在它在 `go test` 里：三手牌、两万多字节、六十九帧，最后屏幕上只剩一帧。判卷用的那个终端模拟器是自己写的五十行，只认三个转义序列——判卷人要小到能一眼看懂，否则是拿一个更大的黑箱去证一个小东西；而且它必须照着 ANSI 的定义写，不能照着被测代码写。

有几样没引，理由也记下来：

全屏 TUI 框架（Bubble Tea、tview 之类）会接管控制流。这个客户端的形状是「事件和键盘汇成一个 select 循环，三种输出格式共用同一条路径」，套进框架之后那条路径会被拆成框架的 Model/Update/View，而 `--format=jsonl` 那一支在框架里无处安放。为了一屏画面把整个客户端的骨架换掉，不划算。

readline 那类行编辑（包括 `x/term` 自己的 `Terminal`）跟固定帧重画是冲突的：它们要独占屏幕最底下那一行，把其余输出当成向上滚动的流水，而这一版恰恰要在上面那片区域就地重画。真想要历史和补全，得先决定放弃固定帧，那是另一个决定。

现成的终端模拟器库只有未打标签的伪版本，而它在这里的角色是判卷人。判卷人用一个没发过版的依赖，比自己写五十行风险大。

**继续守住的一条**：`internal/poker/` 仍然只用标准库，一个第三方库都不能进（ADR-0012）。以前这条不用写测试，因为整个模块没有依赖可违反；现在有了，`internal/poker/deps_test.go` 逐个文件检查 import，内部包和第三方一律报错。牌局核心是 `--seed` 可复现、可见性不变量、单手重放这几件事共同的地基，它不能建在别人下个版本改了什么上。
